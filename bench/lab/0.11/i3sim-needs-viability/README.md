# I3-sim: needs over viability bands on the 0.10.1 engine (the deficit-habit baseline, 2026-10-20)

Mechanism and simulation. The world, arms and episode shape of the v-run (`../v011-viability/`), run on the engine before
RFC 0008: probbit 0.10.1-dev `a5d9c26`, unmodified. Pressure reaches the stance only through six habits on
`need.<id>.deficit` (step functions at fixed thresholds), valence has no need term, and the host keeps the band widths. Arms
A (decides from the stance), B (the same policy on a constant resting stance), C (threshold heuristic on the world's
levels), D (random); evaluation seeds 1000-1999, 1,000 episodes per arm, 400 steps.

This kit reproduces the 0.10.1 column of Table 3 in the technical report (survival A 0.559, B 0.000, C 0.351, D 0.002;
A − B 95 % bootstrap CI [0.528, 0.590]), the reference numbers the v-run's bars were written against (pressure tracking
0.832, valence −0.149, prioritisation 0.9999), the tuned configuration's tracking (0.440, `tracking_best.tsv`), and the
0.10.1 halves of figures a, b and c of `docs/results/0.11/`. It also carries the 240 simulated strands that V5 of the v-run
replays. The bars as registered before the run: [PREREGISTRATION.md](PREREGISTRATION.md).

## Recompute every table (no API calls, no network)

```bash
cd bench/lab/0.11/i3sim-needs-viability
python3 -m venv venv && venv/bin/pip install numpy==2.0.2
PROBBIT=$(command -v probbit) experiments/rerun.sh venv/bin/python
```

`rerun.sh` runs the three frozen configurations (`baseline`, `best`, `best_coupling`), the loop-endpoint check and the
deficit-only ablation twice, compares the sha256 of the 14 tables with `tables/original.sha256` and with each other, prints
one `MATCH` line per table and `tables: byte-identical (original, rerun 1, rerun 2): 14 files`, then verifies the 240 strands it wrote (20 episodes x 4
arms x 3 configurations) with `probbit live verify` and prints `strands: 240 verified, 0 failed`. Strands go to `strands/`
and the generated persona documents to `work/` (neither committed). `git status --short tables` is empty after a
reproduction.

Wall time: 51 min 37 s (3,097 s) on a 16-vCPU Ubuntu 24.04 VM with `PROCS=14` (two passes plus the strand
verification; the loop check and the ablation always run 8 processes). The harness runs 8 processes in parallel;
`PROCS=<n>` sets the number for `run_arms.py` (every episode is seeded, so the tables do not depend on it).

## Files

| file | what |
|---|---|
| `experiments/world.py`, `policies.py`, `persona.py`, `bridge.py`, `run_arms.py` | the world, the policies, the persona (a synthetic simulation persona, built in code), the bridge, the arms and the tables |
| `experiments/config_baseline.json`, `config_best.json`, `config_best_coupling.json` | the baseline, the loop's best configuration, and the best persona with the baseline world |
| `experiments/loop.py` | the 30-minute schedule search on tuning seeds 0-99 (not re-run; its trajectory is `tables/loop_trajectory.tsv`) |
| `experiments/loop_check.py`, `experiments/ablation.py` | the loop's endpoints re-measured on tuning and held-out seeds; the deficit-only ablation |
| `experiments/finalize.sh`, `experiments/rerun.sh` | the post-loop step that froze the two tuned configurations; the double rerun |
| `tables/arms_*.tsv`, `tracking_*.tsv`, `episodes_*.tsv`, `bars_*.tsv` | per configuration: arms, tracking distributions, episodes, bars n1-n3 |
| `tables/loop_check.tsv`, `ablation_baseline.tsv`, `loop_trajectory.tsv` | loop endpoints, ablation, the loop's recorded trajectory |
| `tables/original.sha256`, `rerun-1.sha256`, `rerun-2.sha256`, `strand_verify.txt` | the run's own replay record |

Path lines changed for publication (nothing else): `bridge.py` reads the binary from `PROBBIT`; `run_arms.py` writes the
generated persona documents under `work/`; `rerun.sh` and `finalize.sh` take the interpreter as their argument and
`rerun.sh` the binary from `PROBBIT` and the process count from `PROCS`.

Added after the run (no effect on the tables): `rerun.sh` prints `MATCH <file> <sha256>` or `DIFFERS <file> <sha256>
(committed <sha256>)` per table against `tables/original.sha256` and refuses a Python outside 3.9 to 3.12 (numpy 2.0.2
wheels) unless `PYTHON=<python>` is set, in which case it warns.

Not in this kit: the 240 strands themselves (the rerun writes them), and the loop's run log.
